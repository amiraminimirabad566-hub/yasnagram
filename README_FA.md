# یسناگرام — نسخه مخصوص Cloudflare

این نسخه جایگزین ZIP قبلیِ مخصوص Supabase است. در این بسته، رابط کاربری و API سمت سرور برای Cloudflare Pages Functions و دیتابیس Cloudflare D1 آماده شده است.

## امکانات این نسخه
- رابط فارسی و انگلیسی
- ثبت‌نام و ورود با ایمیل و رمز عبور
- نگهداری نشست ورود با کوکی امن HttpOnly
- فید و انتشار پست متنی
- دیتابیس D1 با جداول کاربران، نشست‌ها و پست‌ها
- بدون نیاز به Supabase یا Firebase

## راه‌اندازی در Cloudflare

### ۱) ساخت دیتابیس D1
1. در داشبورد Cloudflare وارد **Workers & Pages** شو.
2. از بخش **D1 SQL Database** یا **Storage & databases > D1** گزینه ساخت دیتابیس را بزن.
3. نام دیتابیس: `yasnagram-db`
4. دیتابیس را بساز.
5. شناسه دیتابیس (Database ID) را کپی کن.

### ۲) ساخت جدول‌ها
1. دیتابیس `yasnagram-db` را باز کن.
2. وارد بخش **Console** شو.
3. تمام متن فایل `migrations/0001_init.sql` را کپی و اجرا کن.

### ۳) انتشار سایت با Pages
این بسته باید به‌صورت پروژه کد در GitHub قرار بگیرد و سپس به Cloudflare Pages متصل شود؛ ZIP را نمی‌توان مستقیماً به‌عنوان یک سایت Pages منتشر کرد.
1. کل محتویات پوشه `YASNAGRAM_CLOUDFLARE` را در یک مخزن GitHub بارگذاری کن.
2. در Cloudflare برو به **Workers & Pages > Create application > Pages > Connect to Git**.
3. مخزن را انتخاب کن.
4. Build command: `npm run build`
5. Build output directory: `dist`
6. Deploy را بزن.

### ۴) اتصال D1 به Pages
پس از ساخت Pages project:
1. وارد پروژه Pages شو.
2. برو به **Settings > Functions > D1 database bindings**.
3. Add binding را بزن.
4. Variable name را دقیقاً `DB` بگذار.
5. دیتابیس `yasnagram-db` را انتخاب کن.
6. Save کن و یک بار پروژه را دوباره Deploy کن.

### ۵) شناسه در wrangler.toml
اگر بعداً از Wrangler برای توسعه محلی یا انتشار استفاده کردی، مقدار `database_id` در `wrangler.toml` را با شناسه واقعی D1 جایگزین کن. برای اتصال از طریق داشبورد Pages، Binding با نام `DB` ضروری است.

## نکات امنیتی مهم
- رمز عبور با PBKDF2 و ۲۱۰٬۰۰۰ تکرار هش می‌شود؛ رمز خام ذخیره نمی‌شود.
- توکن نشست به شکل هش‌شده در D1 ذخیره می‌شود و کوکی آن HttpOnly و Secure است.
- این نسخه هنوز محدودسازی نرخ درخواست، تأیید ایمیل، بازیابی رمز، تأیید هویت چندمرحله‌ای، پنل مدیریت، گزارش محتوا و سیستم تعدیل محتوا ندارد.
- قبل از عرضه عمومی باید Rate limiting، تأیید ایمیل، گزارش و بررسی انسانی، مسدودسازی حساب، اعتراض، سیاست حریم خصوصی و آزمون امنیتی اضافه شود.
- آپلود عکس و ویدئو عمداً فعال نیست؛ تا قبل از آماده شدن فرایند نظارت محتوایی، رسانه عمومی اضافه نکن.
- هرگز رمزها یا کلیدهای محرمانه حساب Cloudflare را در چت ارسال نکن.

## اجرای محلی (اختیاری)
Node.js نسخه 20 یا جدیدتر لازم است:
```bash
npm install
npm run build
```
برای اجرای API محلی و اتصال D1، از Wrangler و تنظیمات محیط محلی استفاده می‌شود؛ راهنمای کامل توسعه محلی در مرحله بعد اضافه می‌شود.
